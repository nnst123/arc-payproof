# Arc PayProof 参赛项目设计规格

日期：2026-09-20

## 1. 目标与边界

Arc PayProof 是一个一次性 USDC 发票应用。收款人创建发票并分享链接，付款人在 Arc 主网支付，双方都能从链上读取付款状态和交易凭证。项目要以一个能打开、能完成真实小额交易的主网应用参加 Arc Microgrants。

本版本只支持 Arc 上的原生 USDC、单笔全额付款和一位收款人。它不支持托管、退款、部分付款、跨链、自动换汇、订阅、争议处理、用户账户或后台管理。智能合约收到款项后，在同一笔交易中转给收款人；合约不主动保留付款资金。

成功标准：评审者可打开公开网页与代码仓库，使用 Arc 主网钱包创建发票、支付一笔发票、看到已付款状态，并通过区块浏览器核实交易和合约地址。

## 2. 用户流程

### 创建发票

1. 收款人连接钱包；应用确认钱包处于 Arc 主网。
2. 收款人填写公开的用途说明和金额。说明限制为 1–120 个 UTF-8 字节；金额限定为大于零、最多两位小数的 USDC。
3. 前端直接对输入说明的 UTF-8 字节计算哈希，不做大小写或空白归一化，然后调用合约创建发票。合约记录收款地址、金额、说明哈希和未支付状态，生成递增的发票 ID。
4. 交易确认后，前端生成分享链接。链接包含发票 ID 和 URL 编码的用途说明，不包含私钥或其他敏感信息。

### 支付与查看凭证

1. 付款人打开链接。前端从 Arc 主网合约读取收款地址、金额、说明哈希和状态，并校验链接中的说明哈希。
2. 页面清楚显示收款地址、金额和网络。说明哈希不匹配时，不展示支付按钮。
3. 付款人连接 Arc 主网钱包，确认一笔金额恰好等于发票金额的支付交易。钱包另需留有支付手续费的 USDC。
4. 合约先将发票标记为已支付，再把该笔 USDC 转给收款人；转账失败时整笔交易回滚，发票仍为未支付。
5. 前端从链上读取最新状态，并按发票 ID 查询 `InvoicePaid` 事件以取得交易哈希；页面显示付款人地址和 Arc 浏览器链接。任何人再次打开相同链接都能看到已支付状态；重复付款会被合约拒绝。

## 3. 组成与接口

### 智能合约

采用 Solidity 0.8.x，使用 Arc Foundry 进行编译、测试和部署。合约只提供三个外部能力：

- `createInvoice(uint256 amount, bytes32 descriptionHash)`：由调用者创建发票；收款人固定为 `msg.sender`；拒绝零金额。
- `payInvoice(uint256 invoiceId)`：仅接受未支付发票，且要求 `msg.value` 精确等于发票金额；更新状态并原子转账给收款人。
- `getInvoice(uint256 invoiceId)`：读取收款人、金额、说明哈希、状态和付款人。不存在的 ID 返回明确错误。

合约发出包含索引发票 ID 的 `InvoiceCreated` 和 `InvoicePaid` 事件，便于页面通过链上日志恢复创建结果与付款凭证。发票不设置过期时间；本版本也不提供取消功能。金额使用 Arc 原生 USDC 的 18 位链上精度，前端只允许用户输入最多两位小数，避免单位换算错误。

### 网页

采用 TypeScript、React、Vite、viem 和 wagmi，通过 GitHub Pages 部署为 HTTPS 静态站点。页面以查询参数切换创建页和发票详情页，避免静态托管的路径刷新问题。钱包仅用于签署交易；网页不接收私钥。网页从合约读取发票，不依赖数据库或运行中的后端服务。发布时配置主网合约地址，测试环境配置独立的测试网合约地址。

用途说明放在分享链接中，合约只保存其哈希。页面必须提示用途说明与链接会公开；若链接丢失，仍可按发票 ID 查询金额、收款人和状态，但无法恢复说明文本。

## 4. 失败与边界处理

- 钱包未连接或网络错误：显示连接或切换至 Arc 的操作，不发起错误链的交易。
- 钱包 USDC 不足：在交易前提示金额加手续费要求；以钱包最终估算为准。
- 用户拒签、交易回滚或 RPC 暂时不可用：显示具体状态，保留发票链接，并提供重新读取链上状态的操作；不自动重复发送付款。
- 说明哈希不匹配：阻止从该链接付款，并提示重新向收款人索取链接。
- 发票已支付：禁用付款按钮，展示链上状态与付款凭证。
- 无效发票 ID 或金额：给出明确错误，不显示可执行的付款按钮。

## 5. 验证方式

先在 Arc 测试网完成合约测试和两钱包端到端操作，再在主网用小额真实 USDC 验证同一流程。合约测试覆盖创建、精确付款、错误金额、重复付款、无效 ID 和收款失败回滚。网页验证网络切换、说明哈希校验、付款前后状态和交易链接。发布前确认公开仓库未包含私钥、助记词或部署密钥。

主网演示记录至少包含一个成功发票 ID、对应交易哈希、可访问网页和合约地址。评审者不必付款即可查看已完成的示例发票。

## 6. 交付与进度

交付物是：公开的 HTTPS 网页、Arc 主网合约、公开 GitHub 仓库、含安装与验证步骤的 README、简短项目说明、主网演示交易链接，以及提交者的公开 GitHub 开发者主页。DoraHacks 提交时提供网页与仓库链接，并说明 Arc 在项目中的作用。

建议进度：9 月 20–23 日完成设计与页面原型；9 月 24 日至 10 月 1 日完成合约、网页和测试网流程；10 月 2–7 日完成主网部署与小额交易；10 月 8–10 日完善说明并提交。正式截止为 2026 年 10 月 14 日 23:59 美东时间，内部目标提前四天，为钱包、RPC 和部署问题留出余量。

## 7. 依赖与资金控制

Arc 主网创建发票、付款和部署合约都消耗真实 USDC 手续费；演示付款也需要真实 USDC。主网操作前只需为专用演示钱包准备小额资金，不在文档或代码中保存密钥。主网部署及真实付款分别进行人工确认。测试网资金可从 Circle Faucet 获取。

Arc 官方文档给出的主网链 ID 为 5042、RPC 为 `https://rpc.mainnet.arc.io`。上线时以官方文档和实际 RPC 再核对一次。Arc 的原生 USDC 以 18 位精度处理；本项目不把它与 6 位精度的 ERC-20 接口当作两种资产。
